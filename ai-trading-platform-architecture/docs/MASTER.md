## 1. ما هو المشروع

**مساعد تحليل واتخاذ قرار تداول، خاص، يُباع باشتراك شهري، ويُسلَّم عبر بوت تيليجرام عربي بالكامل.**

| | |
|---|---|
| الواجهة | بوت تيليجرام (عربي 100%) |
| الويب | لوحة المالك فقط — **لا تسجيل عام** |
| الهوية | `telegram_id` — لا كلمات مرور للعملاء |
| المخرجات | **إشارات وتحليل فقط** — لا تنفيذ صفقات |
| مفاتيح العملاء | **لا تُجمع ولا تُخزَّن** |
| الدفع | أكواد ترخيص + تفعيل يدوي، مع طبقة مزوّد للتوسع |

### ما ليس هو

- ليس منصة تداول عامة.
- ليس بوت تنفيذ آلي.
- ليس خدمة مجانية أو مفتوحة.

## 2. المبادئ الحاكمة (غير قابلة للتفاوض)

هذه المبادئ تحكم كل سطر في المشروع. مخالفتها = رفض المساهمة.

### 🔒 م1 — العقل نقي (Pure)

كل التحليل دوال نقية: `(candles, config) => report`. لا قاعدة بيانات، لا شبكة، لا تيليجرام داخل `src/lib/intelligence/`.

**لماذا:** يجعل العقل قابلاً للاختبار والتكرار، وصالحاً للاستخدام في البوت والاختبار الخلفي معاً.

### 🔒 م2 — العربية طبقة عرض فقط

المحركات تُصدر رموزاً (`ReasonCode`)، والترجمة العربية في **ملف واحد**: `messages.ar.ts`.

**ممنوع:** كتابة نص عربي داخل `intelligence/`، `engine/`، أو `db/`.

### 🔒 م3 — بوابة صلاحيات واحدة

كل وصول يمر عبر `evaluateAccess()`. لا استثناءات.

**ممنوع:** كتابة `if (subscription.active)` في أي مكان آخر.

### 🔒 م4 — لا تنفيذ صفقات، لا مفاتيح عملاء

واجهة `MarketDataSource` **لا تحتوي** على دالة إرسال أمر. القيد مُرمَّز في نظام الأنواع.

### 🔒 م5 — الرفض نتيجة ناجحة

`wait` و `reject` ليست أخطاء. **كل** قرار يُحفظ — بما فيه الرفض — لأنه المقام الصادق لأي نسبة نجاح.

### 🔒 م6 — الافتراضات المتشائمة

عند لمس الهدف والوقف في شمعة واحدة ⇒ **الوقف أولاً**. لا نغلق صفقة بسعر لم نتحقق منه.

### 🔒 م7 — العتبات مُقاسة لا مُخمَّنة

أي تعديل على محلل أو وزن يستوجب إعادة `npm run calibrate` وتحديث الأرقام.

        ▼
   validateCandles()          ← يرفض البيانات الفاسدة
        ▼
╔═══════════════════════════════════╗
║  العقل — دوال نقية بالكامل        ║
║  8 محللات → confluence → بوابات   ║

        ▼

        ▼

## 4. عقل التداول — كيف يتخذ القرار

### المحللات الثمانية

| المحلل | الوزن | يقيس |
|---|---|---|
| `structure` | 1.8 | هيكل السوق، كسر الهيكل |
| `trend` | 1.6 | ترتيب المتوسطات + الميل |
| `zones` | 1.5 | الدعم/المقاومة، العرض/الطلب |
| `momentum` | 1.2 | RSI + MACD + الدايفرجنس |
| `priceAction` | 1.1 | الابتلاع، ذيول الرفض |
| `liquidity` | 1.0 | اصطياد السيولة |
| `volume` | 0.9 | تأكيد الحجم |
| `volatility` | 0.6 | **بوابة فقط — لا يصوّت على الاتجاه** |

كل محلل يُخرج `score ∈ [-1,1]` و `confidence ∈ [0,1]`.

### معادلة قوة الإشارة

```
confluence = agreement × coverage
```

- **agreement** — متوسط مرجّح بالثقة للمحللات التي **لها رأي** (`|score| ≥ 0.08`).
- **coverage** — كم محللاً تكلم فعلاً (`0.55 + 0.45 × النسبة`).

> ⚠️ **درس مكلف:** المتوسط البسيط كان يعامل الصمت كمعارضة، فيسجل إعداد ممتاز **44** ولا يُصدر البوت إشارة أبداً. الفصل بين "هل يتفقون" و"كم تكلم" هو ما أصلح المحرك.

### العتبة — مُقاسة لا مُخمَّنة

| الحالة | النتيجة |
|---|---|
| سوق عشوائي p50 / p90 / **p99** | 15 / 40 / **47** |
| سوق متذبذب | 19 |
| **العتبة المضبوطة** | **52** |
| إعداد ممتاز (صعود/هبوط) | **55 / 54** |

الفجوة بين 47 و55 **هي المنتج**. أعد التوليد بـ `npm run calibrate`.

### بوابات الرفض (بالترتيب)

الأرخص والأكثر جوهرية أولاً. **أول بوابة تفشل تحدد الحكم.**

| # | البوابة | الحكم |
|---|---|---|
| 0 | بيانات غير كافية | reject |
| 1 | نافذة أخبار | wait |
| 2 | الحد اليومي | wait |
| 3 | فترة تهدئة | wait |
| 4 | صفقة مفتوحة | wait |
| 5 | تقلب حاد | reject |
| 6 | سوق هامد | reject |
| 7 | تعارض الأطر | wait |
| 8 | قوة إشارة < 52 | reject |
| 9 | لا أفضلية هيكلية | wait |
| 10 | **السعر ابتعد > 4 ATR** | **wait** |
| 11 | عائد/مخاطرة ضعيف | reject |
| 12 | احتمالية منخفضة | reject |

### خطة الصفقة

- **الوقف:** أقرب مستوى هيكلي صالح (0.5–4 ATR)، **وليس** آخر قمة/قاع دائماً.
- **إذا وُجد هيكل لكنه بعيد** ⇒ `WAIT_BETTER_PRICE`. **ممنوع** التوسع بوقف ATR — ذلك يُعيد تفعيل مطاردة السعر.
- **الأهداف:** مضاعفات مخاطرة (2R / 3.5R)، لا نسب ثابتة.
- **الحجم:** بحد أقصى **25%** من المحفظة.

> ⚠️ **درس:** المعادلة القياسية `risk% / stop%` أعطت **105%** من المحفظة على وقف ضيق — أي رافعة قد لا يملكها العميل.

### حلقة التعلم

- لا تكيّف قبل **25 عينة**.
- التعديل مُقلَّص نحو المحايد، ومحصور في `[0.7, 1.15]`.
- **تُعايَر الاحتمالية فقط.** حدود المخاطرة سياسة، لا يُسمح للنموذج بتجاوزها.

## 5. النظام التجاري

### الخطط (بيانات في `plans`، وليست كوداً)

| | basic | pro | vip |
|---|---|---|---|
| السعر/شهر | 29$ | 79$ | 149$ |
| العملات | 3 | 10 | الكل |
| تحليل يومي | 5 | 25 | بلا حد |
| التقارير | يومي | +أسبوعي | الكل |
| الأولوية | — | 15 ث | 60 ث |

إضافة خطة = صف جديد + `npm run admin seed`. **بدون نشر.**

### دورة الوصول

```
/بدء → pending ──(كود/تفعيل)──> active → expiring_soon → expired
                                   │
                        المالك: pause / suspend / ban
```

**قواعد مُختبَرة (14 اختباراً):**

- **الحظر يسبق الفوترة** — لا نطلب الدفع ممن نرفض خدمته.
- **الإلغاء يحترم المدة المدفوعة.**
- **الإيقاف المؤقت لا يحذف التاريخ.**
- **`featuresSnapshot`** يمنع خفض مستوى عميل دافع عند تعديل خطة.

### أكواد الترخيص

- تُخزَّن **مُجزَّأة** (SHA-256) فقط.
- أبجدية بلا أحرف ملتبسة (لا `0/O` ولا `1/I/L`).
- الاسترداد **ذرّي**: `UPDATE ... WHERE status='issued'` — التحقق والمطالبة عملية واحدة، فلا يمكن استخدام الكود مرتين حتى مع التزامن. *(مُتحقَّق منه: أول محاولة تُرجع صفاً، الثانية صفر.)*

### أوامر البوت

| الأمر | يتطلب اشتراكاً |
|---|---|
| `/بدء` `/مساعدة` `/الخطط` `/اشتراكي` `/تفعيل` `/الدعم` | ✗ |
| `/الحالة` `/الصفقات` `/الأداء` `/الإعدادات` | ✓ |
| `/تحليل [عملة]` | ✓ + حصة يومية |
| `/تقرير_يومي` `/تقرير_أسبوعي` `/تقرير_شهري` | ✓ + ميزة الخطة |

**تطبيع عربي:** `/الاعدادات` = `/الإعدادات`. تُقبل `بيتكوين` ⇒ `BTCUSDT`.

**أوامر المالك** (`/إحصائيات` `/منح` `/إيقاف` `/إذاعة`) ترد على غير المالك بـ"أمر غير معروف" — لا نكشف لغريب وجود أدوات إدارية.

## 6. قاعدة البيانات

17 جدولاً. الترحيل في `drizzle/` ومُتحقَّق منه على محرك Postgres حقيقي.

| المجال | الجداول |
|---|---|
| الهوية | `customers` · `admin_users` · `admin_sessions` |
| التجارة | `plans` · `subscriptions` · `payments` · `licence_keys` |
| الإشارات | `signals` · `signal_events` · `analysis_snapshots` |
| التعلم | `signal_outcomes` · `calibration` |
| التشغيل | `delivery_log` · `usage_events` · `audit_logs` · `system_settings` · `watched_symbols` |

### قيود تحمي العمل (مُختبَرة)

| القيد | يمنع |
|---|---|
| `customers.telegram_id` فريد | ازدواج الحسابات |
| `(provider, providerRef)` فريد | احتساب دفعة مرتين عند إعادة إرسال webhook |
| `signal_outcomes.signalId` فريد | تكرار النتائج عند إعادة تشغيل المهمة |
| `subscriptions.planId` **RESTRICT** | حذف خطة يستخدمها عملاء دافعون |
| حذف عميل **CASCADE** | صفوف يتيمة |

> ⚠️ **خطأ حقيقي كشفه اختبار التكامل:** كان `firstSeenAt` و `createdAt` يشيران لنفس العمود، ما أسقط حقلاً وكسر **كل** عمليات الإدخال. لم يكشفه التحقق من الأنواع.

**قاعدة:** الأعمدة المالية `numeric` (وليست `float`) وتصل كنص — التحويل مسؤولية طبقة التخزين.

## 7. التشغيل

### التنصيب

```bash
npm install
cp .env.example .env      # املأ القيم
npm run db:migrate        # إنشاء الجداول
npm run admin seed        # الخطط والعملات الافتراضية
npm run admin create-admin owner@example.com 'كلمة-مرور-قوية'
```

### ربط البوت

```bash
curl -F "url=https://YOUR_DOMAIN/api/telegram/webhook" \
     -F "secret_token=$TELEGRAM_WEBHOOK_SECRET" \
     "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook"
```

### المهام المجدولة

كل مهمة: `POST /api/cron/<job>` مع `Authorization: Bearer $CRON_SECRET`.

| المهمة | التكرار المقترح | الوظيفة |
|---|---|---|
| `track` | كل 5 دقائق | متابعة الأهداف/الوقف |
| `scan` | كل 15 دقيقة | البحث عن فرص |
| `outcomes` | كل ساعة | النتائج + المعايرة |
| `expiry` | يومياً 09:00 | تنبيه/إنهاء الاشتراكات |
| `report-daily` | يومياً 20:00 | التقرير اليومي |
| `report-weekly` | الأحد 20:00 | التقرير الأسبوعي |
| `report-monthly` | 1 من الشهر | التقرير الشهري |

### CLI المالك

```bash
npm run admin stats                        # لوحة الأعمال
npm run admin list                         # العملاء
npm run admin issue-keys pro 10 30         # 10 أكواد، 30 يوماً
npm run admin grant 123456789 pro 30       # تفعيل مباشر
npm run admin suspend|activate|ban 123456789
npm run admin pause|resume 123456789
```

> `stats` يعرض **نسبة الانتقائية**. محرك سليم يرفض معظم الوقت — اقتراب الدخول من 100% يعني أن البوابات معطّلة وأن البوت يبيع ضجيجاً.

## 8. الأمان

| الخطر | الإجراء |
|---|---|
| تزوير webhook | مقارنة `secret_token` **بزمن ثابت قبل قراءة الجسم** |
| عاصفة إعادة إرسال | نرد 200 دائماً للتحديثات الموثقة (تيليجرام يعيد المحاولة على غير ذلك) |

| اختراق المالك | جلسة 8 ساعات + أدوار + سجل تدقيق |
| بيانات فاسدة | `validateCandles` قبل العقل |
| تعطل منصة | 3 مصادر + قاطع دائرة |

**ملاحظة تصميمية:** مسار الكرون يرد **500** عند الفشل (عكس الـ webhook) — لأن المجدول *يجب* أن يعيد المحاولة والفشل يجب أن يظهر في المراقبة.

## 11. دليل المطوّر — كيف تضيف ميزة

### إضافة محلل جديد

1. أضف الدالة في `analysers.ts` بنفس التوقيع `(candles) => AnalyserReport`.
2. أضف رموز الأسباب في `types.ts` (`ReasonCode`).
3. أضف الترجمة العربية في `messages.ar.ts` — **الأنواع تُجبرك على ذلك**.
4. سجّله في `analyseTimeframe()` وأعطه وزناً.
5. **أعد `npm run calibrate`** وحدّث الأرقام في `types.ts`.
6. أضف اختباراً في `__tests__/`.

### إضافة أمر تيليجرام

1. أضف `CommandId` و`CommandSpec` في `commands.ts` (حدّد `requiresSubscription` و`metered`).
2. أضف `case` في `runSubscriberCommand` أو `runOpenCommand`.
3. النص العربي في `messages.ar.ts` فقط.
4. **لا تكتب فحص اشتراك يدوياً** — البوابات تعمل قبل وصول التنفيذ.

### إضافة خطة

```bash
# عدّل DEFAULT_PLANS في scripts/admin.ts ثم:
npm run admin seed
```
لا حاجة لتعديل الكود أو النشر.

### إضافة منصة بيانات

1. نفّذ `MarketDataSource` في `adapters.ts`.
2. سجّلها في `buildSources()`.
3. لا شيء آخر يتغير.

### تعديل عتبة قرار

1. عدّل `DEFAULT_BRAIN_CONFIG`.
2. `npm run calibrate` — **يجب** أن تبقى العتبة فوق ضجيج p99.
3. حدّث تعليق الأرقام والاختبارات.
