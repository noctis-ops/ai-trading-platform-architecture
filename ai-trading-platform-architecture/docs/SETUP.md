# دليل التنصيب والتشغيل — Setup Guide

> هذا الدليل **تشغيلي بحت**: كيف تُنصِّب وتُشغّل المشروع وتُشغّل محرك الاختبار الخلفي.
> للعمارة والمبادئ الحاكمة وحدود المنتج، اقرأ أولاً
> [الوثيقة المرجعية `MASTER.md`](MASTER.md). أي خطوة هنا تخالف `MASTER.md`
> تعتبر غير صحيحة.

## ١. المتطلبات

| المتطلب | الأدنى الموصى به | ملاحظة |
|---|---|---|
| Node.js | 22.x | المشروع يستخدم `tsx` و`node:test` |
| مدير الحزم | npm 10+ | |
| قاعدة بيانات | PostgreSQL 14+ | **الاختبارات** تعمل على PGlite (Postgres داخل WASM) بلا خدمة خارجية |
| بوت تيليجرام | `@BotFather` | لامتلاك البوت في الإنتاج فقط |
| شبكة | اختيارية | المصادر العامة (Binance/Bybit/OKX) لا تتطلب مفاتيح API |

> ⚠️ **لا تفعّل `ALLOW_SIMULATED_DATA=true` في الإنتاج.** العملاء يجب أن
> يتلقوا إشارات مشتقة من أسعار حقيقية فقط؛ المحاكي لأغراض الاختبار والبحث.

## ٢. التنصيب

```bash
git clone <repo> && cd ai-trading-platform-architecture
npm install

cp .env.example .env          # املأ القيم (انظر §٣)
npm run db:migrate            # أنشئ جداول PostgreSQL
npm run admin seed            # الخطط والعملات والافتراضيات
npm run admin create-admin owner@example.com 'كلمة-مرور-قوية'
```

للتحقق السريع قبل الإنتاج:

```bash
npm run typecheck
npm run lint
npm test                      # 52 اختباراً (منها 12 على قاعدة بيانات حقيقية)
npm run build
```

## ٣. متغيرات البيئة (`.env`)

| المتغير | الغرض | ملاحظة |
|---|---|---|
| `DATABASE_URL` | رابط PostgreSQL | `postgresql://user:pass@host:5432/db` |
| `TELEGRAM_BOT_TOKEN` | توكن البوت من `@BotFather` | |
| `TELEGRAM_WEBHOOK_SECRET` | سر التحقق من الـ webhook | `openssl rand -hex 32` |

| `ALLOW_SIMULATED_DATA` | مصدر محاكاة احتياطي | **false** في الإنتاج |
| `CRON_SECRET` | سر مهام الكرون | `openssl rand -hex 32` |
| `MAX_SIGNALS_PER_DAY` | سقف الإشارات اليومي | 6 |

> `minConfluence` **غير** قابل للضبط عبر `.env` عمداً — هو مُقاس بدراسة
> (`npm run calibrate`) ولا يُخفَّض بأمر. غيّره فقط بإعادة المعايرة.

## ٤. قاعدة البيانات

الترحيل في `drizzle/` ومُتحقَّق منه على Postgres حقيقي.

```bash
npm run db:migrate            # طبّق الترحيلات الموجودة
npm run db:generate           # ولّد ترحيلاً جديداً بعد تعديل `src/db/schema.ts`
```

الاختبارات لا تحتاج PostgreSQL منفصلة: تستخدم PGlite (Postgres مُجمَّع إلى
WASM داخل العملية)، فلا خدمة خارجية ولا إعداد.

## ٥. ربط البوت وتشغيله

```bash
npm run dev                   # وحدة التطوير (Next.js)
```

ربط الـ webhook (مرة واحدة):

```bash
curl -F "url=https://YOUR_DOMAIN/api/telegram/webhook" \
     -F "secret_token=$TELEGRAM_WEBHOOK_SECRET" \
     "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook"
```

المهام المجدولة (كل مهمة: `POST /api/cron/<job>` مع
`Authorization: Bearer $CRON_SECRET`):

| المهمة | التكرار المقترح |
|---|---|
| `track` | كل 5 دقائق (متابعة الأهداف/الوقف) |
| `scan` | كل 15 دقيقة (البحث عن فرص) |
| `outcomes` | كل ساعة (النتائج + المعايرة) |
| `expiry` | يومياً 09:00 |
| `report-daily` | يومياً 20:00 |
| `report-weekly` | الأحد 20:00 |
| `report-monthly` | 1 من الشهر |

## ٧. محرك الاختبار الخلفي (v2.2)

المحرك **يعيد تشغيل مسار `decide()` الحرفي** الذي يستخدمه البوت المباشر،
فلا يمكن لرقم مطبوع أن ينحرف عن العقل المُشحون. العقل نقي، فلا يحتاج أي
تعديل — فقط حاضنة تغذّيه نوافذ شموع تاريخية وتُصفّي الصفقات بصدق.

```bash
# كل الرموز، بيانات المحاكاة الافتراضية (سريع)
npm run backtest

# رموز محددة، تاريخ أطول
npm run backtest -- --symbols BTCUSDT,ETHUSDT --bars 8000

# تحقق أمامي زاحف (out-of-sample) — يرفع --bars تلقائياً إلى 8000
npm run backtest -- --symbols BTCUSDT --walk-forward

# ضبط خطوات التحقق
npm run backtest -- --walk-forward --train-bars 3000 --test-bars 1500
```

الأعلام:

| العلم | الافتراضي | الوظيفة |
|---|---|---|
| `--symbols` | كل الرموز العشرة | قائمة مفصولة بفواصل |
| `--bars` | 4000 | عدد شموع الإطار الأدق (15m)؛ أكبر = تاريخ أعمق |
| `--step` | 1 | وتيرة اتخاذ القرار (بالشموع) |
| `--walk-forward` | — | قوائم تدريب/اختبار متتابعة خارج العينة |
| `--train-bars` | 3000 | طول التدفئة في التحقق الأمامي |
| `--test-bars` | 1500 | طول نافذة الاختبار خارج العينة |

### ما يضمنه المحرك (صدق الأرقام)

- **يعيد تشغيل `decide()` حرفياً** — نفس البوابات، نفس العتبات، نفس الخطة.
- **يُسجّل كل قرار** بما فيه الرفض (`wait`/`reject`). الانتقائية = القرارات
  الداخلة ÷ كل القرارات؛ محرك سليم يرفض معظم الوقت.
- **ملء متحفظ:** شمعة تَمَس الوقف والهدف معاً تُصفى عند **الوقف أولاً**
  (الأسوأ افتراضاً) — لا نفترض تحقق الهدف لرفع نسبة النجاح.
- **إدارة الوقف كالبوت المباشر:** عند TP1 يُنقل الوقف إلى بريفين (الصفقة
  تصبح بلا خسارة)؛ عند TP2 يُغلق المركز كاملاً عند +3.5R؛ وإن لَمس السعر
  البريفين لاحقاً تُغلق كـ "scratch" (0R) لا كخسارة.
- **التحقق الأمامي الزاحف:** نوافذ خارج العينة متتابعة، والإعداد **لا
  يُعاد ضبطه** على كل نافذة — إعادة الضبط لكل طيّة هي بالضبط الملاءمة
  المفرطة التي يوجد هذا التمرين لتجنّبها.

### ⚠️ أمانة البيانات — اقرأ هذا قبل نشر أي رقم

بالافتراضي يركض المحرك على **المحاكي الحتمي** (GBM تركيبي). أرقامه تُثبت
أن **الحاضنة موصولة correctly** — أن العقل يتخذ صفقات حقيقية وأن الرفض
يُسجَّل وأن الملء متحفظ. هي **ليست ادعاءً بالأداء** ولا يجوز عرضها على
عميل.

قبل نشر أي نسبة نجاح أو توقّع أو أقصى تراجع:

1. غذّ المحرك **شموعاً تاريخية حقيقية** (نفّذ `MarketDataSource` حقيقياً أو
   حمّل ملف بيانات) — المحرك مجرّد عن مصدر البيانات فيأخذ أي شموع.
2. شغّل البوت **ورقياً في الإنتاج** 4–8 أسابيع قبل أول عميل (v2.2.3 في
   `MASTER.md §10`).
3. احسب الإحصائيات على **كل** القرارات، لا على الصفقات الرابحة فقط.

## ٨. المعايرة

`minConfluence` مُقاسة لا مُخمَّنة. أعد إنتاج الأدلة بعد أي تعديل على محلّل
أو وزن:

```bash
npm run calibrate
```

يجب أن يبقى الحد فوق ضجيج p99 (~47) وتحت إعداد حقيقي (~54–55).

## ٩. أدوات المالك (CLI)

```bash
npm run admin stats                        # لوحة الأعمال + نسبة الانتقائية
npm run admin list                         # العملاء
npm run admin issue-keys pro 10 30         # 10 أكواد، 30 يوماً
npm run admin grant 123456789 pro 30       # تفعيل مباشر
npm run admin suspend|activate|ban 123456789
npm run admin pause|resume 123456789
```

> `stats` يعرض **نسبة الانتقائية**. محرك سليم يرفض معظم الوقت — اقتراب
> الدخول من 100% يعني أن البوابات معطّلة والبوت يبيع ضجيجاً.

## ١١. استكشاف الأخطاء

| العرض | السبب المحتمل | الحل |
|---|---|---|
| `no migration files found` | لم تُولَّد الترحيلات | `npm run db:generate` |
